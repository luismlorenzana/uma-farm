The short answer

  • Who works stays as built (FM6): every outfit (272), 60 slots, her trade by calling. The caps need about 4 to 10 Umas; the rest is headroom for Craft Levels. Measured after your play; the recommendation is no change.
  • Targets become orders: one standing order per item a game accepts, sized to its daily cap ("uma-quest wants 10 Tonics a day"), shown on every place through uma-rpg's own target cascade.
  • No currency. Time makes items, the Forge turns made items into the games' items, the games' caps set the demand. Speed Tickets return only as the Forge's reward: one per Masterwork play, ten held.
  • The Forge is a 25–30 second smithing game: hold to heat, twelve strikes on the item's own rhythm, one quench. Timing only. Inputs are never lost: an unfinished play counts as Rough.
  • Four Forge items: uma-quest's Tonic, Party Meal and Revive; uma-racer's Rosette. uma-rpg takes its made items as they are.
  • The Post sends one parcel a game a day with one tap: Packed, Sent, Claimed, or Refused with Take back.
  • Next: F8 the Forge, F9 its art (ChatGPT), F10 the Post and sender, and uma-platform's PO1 (uma-post 0.1.0).

2 · Targets become orders (FS4–FS7)

uma-rpg's targets marked Umas and listed what maxing their gear took; the farm has no gear. An order is a game's item and a count a day: one standing order per accepted item, sized to that game's cap, on for live receivers. You can switch one off, lower it or change its grade; nothing else to set.

Where surplus goes (FS10)

  1. Made items to uma-rpg as they are, within its caps.
  2. The outbox holds at most a week of each item's cap (70 Tonics, 35 Party Meals, 21 Revives, 7 Rosettes); the Forge greys an item there.
  3. Everything else stays in the Warehouse, which has no limit; the order strips show what's spare.

Speed Tickets' bound (FS9)

About two to eight plays a day fill the orders, and the outbox holds a week, so a perfect player earns about 4 tickets a day: two hours off jobs, 300 Craft EXP, a twelfth of one Uma's day.

4 · The Forge (FS12–FS21)

A place without slots on the map's sixth row; the player is the smith. A game is chosen first (FM9). It makes uma-quest's and uma-racer's items; uma-rpg's made items go as they are through the Post. Its cost is its inputs and nothing else: no fee, no cooldown, no Uma (FS21).

Rhythms (FS18): each item its own, fixed, never random

No gap is under 0.6 s, so two beats' ±200 ms windows never overlap. The tempo doesn't change with grade: progress never makes the game harder. Practice plays any item with no inputs and makes nothing; your best a item is kept.

On the phone (FS19): portrait 390 × 844, the lower 40% one thumb target

Never losing inputs (FS17)

  1. Start moves the inputs into forge.current, one commit.
  2. The result clears it and puts the tier's yield in the outbox, one commit.
  3. Unfinished (closed, hidden, crashed, ✕): settles as Rough next time the Forge opens.
  4. No retries: the worst case is always the base yield, never less, never a free second try.

The scene and the code (FS20)

  • A Phaser scene in its own lazy chunk (LAZY_MODULES); Phaser is already on the device from the map.
  • The rules are pure @farm/domain: recipes, yields, rhythms and scoreForge(item, presses), tested from press times alone.
  • Timing from pointerdown's timestamp; no haptics (iOS web has none); a synthesized clang, no audio files.
  • Placeholders until F9: uma-art's forge, its tonic and feast icons, code-drawn anvil, ring, gauge and bar.

5 · Accept lists and caps (FS22–FS27)

Each game owns its list and caps in uma-post; the farm offers only what a list holds and packs within its caps, and the receiver runs the same checkParcel. A day is the farm's local date stamped on the parcel; one parcel a game a day, so however late a game fetches, it never takes more than its caps for any one day.

uma-post 0.1.0's shape (FS27), what PO1 builds

export const POST_GAMES = ['uma-quest', 'uma-rpg', 'uma-racer'] as const
export type PostGame = (typeof POST_GAMES)[number]

export interface ParcelLine { item: string; qty: number }   // an id on the game's list; qty 1 … its cap

export interface Parcel {
  v: 1                    // the format's version
  id: string              // 'p-' + 20 base32 characters, made by the farm, unique for good
  to: PostGame
  day: string             // 'YYYY-MM-DD', the farm's local date; one parcel a game a day
  items: ParcelLine[]     // at least one line, each item once, sorted by id
  packedAt: string        // ISO time
}

export type ParcelState = 'sent' | 'claimed' | 'refused'          // farm-api's record; never in a save
export type RefusalReason = 'unknown-item' | 'over-cap' | 'bad-qty' | 'repeated-item' | 'wrong-game' | 'repeated-day'

export interface Accepted { item: string; name: string; group: string; tier?: number }
export interface AcceptList { game: PostGame; version: number; items: readonly Accepted[]; caps: Readonly<Record<string, number>> }
export const ACCEPT_LISTS: Readonly<Record<PostGame, AcceptList>>

export function parseParcel(x: unknown): Parcel                                   // throws ParcelParseError
export function checkParcel(p: Parcel, list?: AcceptList): RefusalReason | null
export function capsLeft(list: AcceptList, lines: readonly ParcelLine[]): Record<string, number>

export interface ParcelsReply { parcels: Parcel[] }                                       // GET /api/post/parcels
export interface ClaimsRequest { claimed: string[]; refused?: { id: string; reason: RefusalReason }[] }  // POST /api/post/claims
export interface ClaimsReply { claimed: string[]; refused: string[]; unknown: string[] }                // repeats are no-ops
